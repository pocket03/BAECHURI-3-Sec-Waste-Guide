## 1. 배경 및 문제 정의

익산시 신동 원룸촌에서 외국인 유학생과 집주인 사이에 **정확한 정보가 다국어로 전달되지 않아** 오해와 분쟁이 반복된다. 핵심은 "누가 몰라서 잘못했다"가 아니라, **양쪽이 서로에게 정보를 정확히 전달할 방법이 없다**는 것이다.

### 1.1 왜 집주인이 유일한 통로인가

외국인 세입자에게 "이 동네 규칙"을 알려줄 수 있는 주체를 전부 나열하면, 집주인을 제외하고 전부 결격 사유가 있다.

| 주체 | 접점 | 결격 사유 |
|---|---|---|
| 지자체 | 안내문·포털 | 일반론 PDF다. 누가 어느 건물에 사는지 모르고, 읽었는지도 모른다 |
| 이웃 주민 | 없음 | 언어가 안 통하고, 말 걸 권한도 없다 |
| 대학 국제처 | 재학생 한정 | 근로자·비유학생 제외, 주거는 소관 업무가 아니다 |
| 부동산 중개소 | 계약 시점 1회 | 계약이 끝나면 관계도 끝난다 |
| **집주인** | **상시** | **연락처·권한·반복 접촉·현장 인지를 모두 가짐. 없는 건 언어 하나뿐** |

배추리 매니저는 집주인을 관리자로 만들어주는 서비스가 아니라, 집주인에게 없는 단 하나 — **"언어"를 채워주는 서비스**다. 이 프레이밍은 (1) 사회적 가치를 세입자·동네 쪽에 유지하고, (2) 지자체 정적 자료와의 차별점(누구에게 전달됐는지 안다)을 만들고, (3) 집주인이 시간을 쓰는 이유를 "편해서"가 아니라 "본인만 할 수 있는 일이라서"로 정당화한다.

| 역할 | 누구 | 왜 |
|---|---|---|
| 수혜자 | 외국인 세입자 | 오배출·분쟁·불이익을 겪지 않게 됨 |
| 수혜자 | 동네 주민·다른 세입자 | 갈등 원인이 줄어듦 |
| 고객(사용 주체) | 집주인 | 유일한 접점이므로 유일하게 도구가 필요한 사람 |

### 1.2 이 문제가 실제로 드러나는 두 국면

**국면 A — 일상의 반복 마찰: 분리배출.** 한국식 종량제·분리배출 제도를 언어 장벽 때문에 이해하지 못해 무단투기·오배출이 반복된다. 뉴스 보도, 서울시 시민제안[^1], 서대문구 등 지자체의 다국어 안내 사례[^2], 유학생 25.3만 명 통계(전국 단위 근거는 서비스기획안 1절 참고)가 이를 뒷받침한다. 익산 신동 현장에서도 팀원 자취방 앞 분리수거장이 상시 엉망이고, 신동 일대에 외국인 전용 마트·통신사 대리점이 새로 생길 만큼 외국인 거주 규모가 있다는 점, 대학가 원룸촌 무단투기가 익산만의 문제가 아니라는 점(고려대 법대후문 사례[^3])이 확인됐다. 다만 익산 신동 자체의 등록외국인 통계·시청 민원 자료는 아직 확보되지 않아 향후 보완이 필요하다.

**국면 B — 계약·생활의 소통 단절: 임대차.** 외국인은 원룸을 구하는 단계부터 언어장벽 때문에 지인 도움 없이는 계약이 어렵고[^4], 계약 종료 후에도 정보 비대칭으로 인한 분쟁이 문서화되어 있다 — "외국인 유학생 등쳐먹기"라는 법률 칼럼은 집주인이 일방적으로 수리비를 부풀려 보증금에서 공제하는 사례를 다루고[^5], 보증금 미반환 분쟁 대응 가이드도 별도로 존재한다[^6]. 즉 언어장벽·정보 비대칭은 **집주인이 아니라 오히려 외국인 세입자가 불리해지는 방향으로도 작동**한다.

> **주의**: "외국인 세입자가 청소를 안 하고 몇 개월 살다 도망간다"는 주장과 "무단투기 시 건물주가 과태료를 낸다"는 주장은 검색으로 뒷받침할 근거를 찾지 못했다(폐기물관리법상 과태료는 신고제로, 목격·증거를 통해 특정된 행위자에게 부과되는 것이 원칙[^7][^8]). 두 주장 모두 이 문서와 발표 자료에서 사용하지 않는다. 서비스는 "집주인 편"이 아니라 **양쪽에 표준화된 다국어 정보를 동일하게 제공해 오해·분쟁을 줄이는 중재 도구**로 포지셔닝한다.
>
> 갈등 관련 통계를 인용할 때도 "외국인 관련 갈등이 심각하다/급증한다"처럼 과장하지 않는다. 실태조사는 "갈등 경험 자체는 낮은 편"으로 나오는 경우가 많아 총량을 부풀리면 바로 반박당한다. 쓸 수 있는 프레임은 "갈등의 총량이 크다"가 아니라 **"갈등이 생겼을 때 언어장벽 때문에 풀 수단이 없다"**이다.

### 1.3 왜 "분리배출"을 첫 사례로 골랐는가

집주인-세입자 소통 문제는 여러 형태로 나타날 수 있다. 아래 후보를 비교 검토한 결과, 분리배출이 근거와 실행 가능성 모두에서 가장 강해 **첫 대표 시나리오이자 MVP의 실제 구현 대상**으로 선택했다.

| 후보 | 증거 강도 | 3초 아이콘 확인 UX에 적합한가 |
|---|---|---|
| **분리배출/쓰레기 처리** | 강함 — 뉴스 보도, 서울시 시민제안, 서대문구 사례, 유학생 통계, 팀원 직접 관찰 | **적합** — 매일 반복되는 짧은 판단이라 아이콘 확인 패턴과 맞음 |
| 임대차 계약 체결 | 중간 — 언어장벽으로 계약이 어렵다는 자료 있음 | 부적합 — 일회성·복잡한 문서 이해가 필요해 상담 형태가 더 맞음 |
| 보증금/퇴실 분쟁 | 중간 — 법률 칼럼·로펌 블로그 각 1건 | 부적합 — 위와 동일 |
| 소음/이웃 갈등 | 약함 — 커뮤니티 익명 게시글 수준 | 애매함 |
| 관리비/공과금, 방역 공지 | 근거 못 찾음 | - |

임대차 관련 마찰(국면 B)은 이번 3주 MVP에서 직접 해결하지는 않지만, **집주인용 알림톡의 "퇴실 청소 안내" 템플릿**으로 접점을 만들어둔다(5절).

## 2. 목표

- **1차 목표**: 발표에서 "집주인이 QR·알림톡을 세입자에게 전달"하는 유통 스토리 → "세입자가 3초 만에 신호등·아이콘으로 확인"하는 사용자 데모, 두 흐름이 하나의 시나리오로 끊김 없이 연결된 데모를 완성한다.
- **2차 목표**: 4개 언어 전환이 Must 기능 범위(검색, 신호등, FAQ, QR, 알림톡)에서 최소 P0 언어(한·영)만큼은 깨지지 않는다.

### KPI (팀 내부 테스트 기준)

| 지표 | 목표 |
|---|---|
| 검색 성공률 | 팀원이 아이콘만 보고 60초 이내 품목 찾기 성공 |
| 언어 전환 정상 동작률 | P0 언어(한·영) 100%, P1 언어(중·베)는 핵심 화면만이라도 깨짐 없음 |
| QR 시연 → 결과 표시 | 3초 이내 |
| 오늘의 신호등 정확도 | 요일별 배출 규칙과 100% 일치 |
| 발표 임팩트 | "언어장벽·정보 비대칭" + "익산 신동 근거" + "양쪽을 위한 중재 도구"라는 논리가 한쪽 편들기 없이 전달되는지 |

## 3. 범위 (Scope)

### 3.1 서비스 정체성

- **서비스명**: 배추리 매니저 (BAECHURI Manager)
- **핵심 가치 제안**: 집주인과 외국인 세입자가 언어장벽 없이 정확한 정보를 주고받는 다국어 소통 도구. 첫 대표 시나리오는 분리배출(3초 만에 사진/아이콘으로 확인)이며, 집주인용 알림톡에 원룸 공지사항 카테고리를 더해 소통 범위를 넓힌다.
- **핵심 페르소나 (발표용, 가상 인물)**: 집주인 김OO 씨(60대, 외국어 불가, 익산 신동에서 원룸 운영) — 세입자 응웬OO 씨(20대, 입국 3개월 차 베트남 유학생, 한국어 초급).
- **1차 사용자(소비)**: 익산시 신동 원룸촌 외국인 유학생
- **유통 주체(공급)**: 외국인 세입자를 두는 원룸 집주인(주 채널) 및 부동산 중개업소(보조 채널)

**차별화 논리 — "매뉴얼이 아니라 타이밍".** 정적 번역 자료는 서울시 PDF와 다를 게 없다. 이기는 지점은 번역 자체가 아니라 개인화된 타이밍이다.

| | 공공 안내문 | 배추리 매니저 |
|---|---|---|
| 내용 | 전국 일반론 | 이 건물, 이 동, 이번 주 배출 규정 |
| 전달 | 벽보/포털 게시 | 배출 전날 밤 알림(신호등), 입주 시 알림톡 |
| 도달 확인 | 불가능 | 결과 카드 조회 시점으로 확인 가능 |
| 갱신 주체 | 지자체가 개정할 때만 | 집주인이 알림톡으로 직접, 수시로 |

### 3.2 유통 전략

유학생이 스스로 앱을 찾아 설치하기를 기대하는 대신, **관리 부담·민원 스트레스라는 확실한 pain point를 가진 집주인**을 1차 유통 공급자로 설정한다. 집주인이 입주 계약 시 "다국어 알림톡 + QR 코드"를 세입자에게 전달하는 B2B2C 구조를 만들어 세입자의 실제 접촉 가능성을 높인다.

이 유통 전략은 실제 집주인 섭외·검증 없이 구성한 개념 제안이다. 발표 시 "실배포·실사용자 검증 이전 단계"라는 한계를 명확히 밝힌다(11절).

앱 설치가 아니라 QR/웹 방식을 택한 데도 근거가 있다. 중국 본토에서 판매되는 안드로이드 폰은 구글 플레이스토어가 기본 탑재되지 않아[^9], 네이티브 앱으로 만들면 중국 유학생(P1 지원 언어 대상)이 앱을 찾을 수도 설치할 수도 없다. Next.js 웹 기반(로그인·설치 없음) 아키텍처는 이 문제를 원천적으로 피해간다.

### 3.3 경쟁 인지 및 차별화

"집주인이 세입자에게 공지를 보낸다"는 기능 자체는 새롭지 않다. **자리톡(누적 이용 500만 이상)이 이미 카톡 고지서 무료 발송·월세 알림 기능을 제공 중이다**[^10]. 집요정·렌티·마이집사 등 원룸 임대관리 앱도 유사 기능이 있다.

- 발표에서 "공지 발송" 자체를 차별점으로 내세우지 않는다 — 이미 있는 기능이다.
- **차별점은 다국어(한·영·중·베) 지원이다.** 자리톡 등 기존 임대관리 앱은 한국어 단일 언어 기준이며, 외국인 세입자를 위한 다국어 지원이 확인되지 않는다.
- 서울시 등 지자체의 다국어 자료(6~10개 언어)와도 다르다 — 지자체는 "누구에게 전달됐는지" 모르는 일반론 PDF지만, 우리는 "이 건물, 이 요일"이라는 개인화된 타이밍으로 전달한다.

### 3.4 윤리 가드레일

집주인용 알림톡이 세입자에게 부당하거나 차별적인 공지(예: 특정 시간 이후 외출 금지, 방문객 제한 등)를 다국어로 확산시키는 통로로 악용될 위험이 있다. 이를 막기 위해 다음을 설계 원칙으로 못박는다.

| 장치 | 내용 |
|---|---|
| 템플릿 화이트리스트 | 집주인은 자유 작문이 아니라 **사전 승인된 5개 템플릿(쓰레기 2·퇴실 1·공지사항 2)만 선택 가능**. 새 카테고리를 임의로 추가할 수 없다 |
| 법적 통지 아님을 명시 | 퇴실/청소비 관련 안내는 참고용 안내이지 법적 효력이 있는 통지가 아님을 결과 카드 문구에 명시한다. 번역 오류로 인한 법적 분쟁 소지를 차단하기 위함 |

### In-scope

1. 아이콘/사진 기반 품목 검색 (30개, 확정 완료)
2. 다국어 지원 — 한국어·영어·중국어·베트남어 (우선순위는 8절)
3. QR 현장 가이드 웹페이지 — 시연용(발표 중 스마트폰으로 QR 스캔)
4. 인포그래픽 카드 UI
5. 오늘의 배출 가능 요일 3초 신호등
6. FAQ 버튼형 챗 UI
7. 집주인용 다국어 알림톡 생성기 — 쓰레기 배출 안내 2개 + 퇴실 청소 안내 1개 (Must)
8. 집주인용 알림톡 — 원룸 공지사항 카테고리 2개 추가 (Should, 5개 템플릿 상한 고정)

### Out-of-scope (3주 내 하지 않음)

- 자유 텍스트/음성 챗봇, AI 카메라 인식, 위치 기반 지도, 주민 제보 게시판 (향후 로드맵으로 이관)
- 실제 웹 배포(Vercel 등), QR 실물 인쇄·부착, 실제 집주인 섭외·계약 연동 — 시연 데모로 범위 한정
- 외부 사용자(실제 유학생·집주인) 대상 검증 — 팀 내부 테스트로 대체
- 대학 국제교류처·지자체 연계(B2G), 비자·등록금 등 학사 일정 통합 — 3주 스코프를 크게 초과해 기각
- 집주인 알림톡 카테고리는 **5개 템플릿(쓰레기 2 + 퇴실 1 + 공지사항 2)으로 상한을 고정**한다. 수도 점검, 소음, 주차 등 추가 카테고리는 근거도 없고(1.3절) 번역량도 늘어나므로 넣지 않는다.

## 4. 사용자 시나리오 / 화면 흐름

배추리 매니저는 사이트에 처음 접속하면 **집주인 화면이 먼저 뜬다.** 1.1절에서 확인했듯 집주인이 이 서비스의 실제 진입점이자 고객이기 때문이다. 세입자는 집주인이 전달한 링크나 QR을 통해 별도 경로로 들어온다 — 두 플로우는 순서상 이어지지만, 화면 소유자는 서로 다르다.

**집주인 플로우** (루트 경로 `/` — 앱의 첫 화면):

| 화면 | 사용자가 하는 일 | 다음 |
|---|---|---|
| 집주인 알림톡 생성기 | 상황 버튼(쓰레기 배출 2개 / 퇴실 청소 1개 / 공지사항 2개) 선택 → 4개국어 조합 문장 미리보기 확인 → 전체 복사해 카톡 발송 + 세입자용 링크(또는 건물 QR) 복사 | 세입자에게 링크·QR 전달 |

**세입자(유학생) 플로우** (집주인이 전달한 링크·QR로 진입, 언어 선택부터 시작):

| 순서 | 화면 | 사용자가 하는 일 | 다음 화면 |
|---|---|---|---|
| 1 | 언어 선택 화면 (`/guide`) | 4개 언어 중 하나 선택 (전역 토글, 이후 언제든 변경 가능) | 메인/아이콘 검색 화면 |
| 2 | 메인/아이콘 검색 화면 (`/search`) | 상단 "오늘의 요일 신호등" 확인 → FAQ 퀵 버튼 또는 하단 품목 아이콘 그리드에서 선택 | 결과 카드 화면 |
| 3 | 결과 카드 화면 (`/result`) | 선택한 언어로 배출 방법·요일·주의사항 확인 | 검색 화면 복귀(종료) |
| QR 진입 | (결과 카드 화면으로 직행) | 분리수거장 QR 스캔 → 해당 장소 규정이 담긴 결과 카드로 바로 진입 | — |
| 카톡 링크 진입 | (결과 카드 화면으로 직행) | 집주인이 보낸 알림톡 링크 클릭 → 해당 공지사항이 담긴 결과 카드로 바로 진입 | — |

QR 진입과 카톡 링크 진입은 별도 화면을 새로 만들지 않고, 동일한 "결과 카드" 컴포넌트를 쿼리 파라미터(장소 ID 또는 알림 카테고리 ID)로 분기해 재사용한다. 세입자 화면에서 언어를 바꾸고 싶으면 언제든 `/guide`로 돌아갈 수 있다 — 집주인 화면(`/`)으로는 돌아가지 않는다.

## 5. 기능 요구사항 — MoSCoW 우선순위

언어 우선순위(P0/P1, 8절)와는 별개의 축으로 관리한다.

### Must (필수 구현 — MVP 데모 핵심)

1. **아이콘/사진 기반 품목 검색**: 익산 신동 자취생 빈출 품목 30개(6절) 그리드. 정확한 한글 품목명을 몰라도 선택 가능해야 함.
2. **오늘의 배출 가능 요일 3초 신호등**: 메인 상단에 요일별 배출 가능/금지 품목을 3색 신호등(🟢/🔴)으로 표시. `Date.getDay()` + 정적 요일 규칙 JSON.
3. **FAQ 버튼형 챗 UI**: 자유 텍스트 입력창 없이, 유학생 빈출 질문 3~4개를 퀵 버튼으로 배치. 클릭 시 말풍선 형태로 사전 작성된 답변 노출.
4. **QR 현장 가이드(시연용)**: 장소별 쿼리 파라미터 기반 인포그래픽 카드 노출. 최소 1개 가상 장소 기준 동작 확인.
5. **인포그래픽 카드 UI**: 텍스트 최소화, 그림·아이콘 중심.
6. **집주인용 다국어 알림톡 생성기**(카톡 말풍선 UI, 단일 탭): 상황 버튼 클릭 시 한국어 + 4개국어(영·중·베) 조합 문장 자동 생성 + 텍스트 복사 버튼 + 건물 QR 이미지 다운로드. 템플릿 범위: 쓰레기 배출 안내 2개 + 퇴실 청소 안내 1개.

### Should (권장 구현 — 게이트 미달 시 1순위 드랍)

7. **집주인용 알림톡 — 공지사항 카테고리 확장**: Must 6번과 같은 구조에 "원룸 공지사항"(입주 생활수칙, 방역 안내 등) 템플릿 2개 추가. 번역량이 늘어나므로 Should로 관리한다. 템플릿 총합은 5개(쓰레기 2 + 퇴실 1 + 공지사항 2)로 고정.

### Could (선택/카피 수정 — 개발 공수 0)

8. **배달용기 우선 노출**: 신규 화면 없이 기존 품목 아이콘 그리드 상단에 배달용기 관련 품목 우선 배치.
9. **보증금/민원 안내 카피**: 결과 카드 하단에 "기름때를 씻지 않으면 관리 민원 소지가 있음" 수준의 안내 문구 추가(구체적 금액 표기 시 익산시 조례 원문으로 재검증 필요).

## 7. 기술 스택 및 개발 담당

- **스택**: Next.js + localStorage, 백엔드·로그인 없음, 정적 JSON i18n, 정적 QR 생성 라이브러리. 신호등·FAQ 챗 UI·집주인 알림톡 생성기 모두 정적 데이터 + 클라이언트 로직만으로 구현 가능해 이 원칙을 벗어나지 않는다.
- **개발 담당**: 팀 5인 중 명시적 개발자가 없으므로, 기획·마케팅 3인 중 1인을 "PM 겸 개발 담당"으로 지정하고 AI 코딩 어시스턴트(Claude Code 등)를 활용해 직접 구현한다.
- 이 결정 자체가 최대 리스크이므로 1주차 게이트 체크를 반드시 통과해야 한다(9절).

| 익산 신동 배출 규정 조사가 오래 걸릴 수 있음 | 익산시청 공고 1건만 기준으로 삼아 시간 초과 방지, 1주차 게이트 최우선 항목으로 관리 |
| 실배포·실물 QR이 없어 "실제 현장 적용"까지는 증명 못 함 | MVP 목표를 "개념 증명 + 발표용 데모 완성도"로 명확히 설정 |
| 집주인 유통 전략이 실제 검증되지 않은 가설임 | 발표에서 "실집주인 섭외 이전 단계의 개념 제안"임을 명확히 밝히고, 근거 약한 주장(과태료 등)은 사용하지 않음 |
| 헷갈리는 품목(달걀껍질·깨진그릇·치킨박스 등)의 배출법 오기재 위험 | 익산시 공식 자료로 재검증 후 콘텐츠 확정, 애매한 경우 환경부 가이드라인으로 교차 확인 |
| 알림톡 카테고리를 늘리며 번역량이 20개 문자열로 증가 | 템플릿 5개 상한 고정, 공지사항 카테고리(Should)부터 드랍 가능하게 방어선을 둠 |
| "왜 소통 플랫폼인데 분리배출 얘기만 하나"는 지적 가능성 | 페르소나로 "분리배출은 소통 단절의 가장 흔하고 검증된 첫 사례"라는 서사로 연결, 1.3절 비교 검토 결과를 근거로 제시 |
| "공지 발송" 기능이 자리톡 등 기존 임대관리 앱과 겹쳐 보일 위험 | 발표에서 "공지 발송"이 아니라 "다국어 지원"만을 차별점으로 명시 |
| 집주인 알림톡이 차별적 공지 확산 통로로 악용될 위험 | 템플릿 화이트리스트(사전 승인된 5개만)로 자유 작문 원천 차단 |
| 퇴실/청소비 안내가 법적 통지로 오인될 위험 | 결과 카드에 "참고용 안내이며 법적 효력이 있는 통지가 아님"을 명시 |

## 12. 향후 로드맵 (3주 이후, 참고용)

1. 자유 텍스트/음성 기반 챗봇(LLM API 연동), AI 카메라 인식(GomiSense류)
2. 언어 확대(태국어·몽골어 등)
3. 위치 기반 지도, 주민 제보 게시판
4. 대학 국제교류처·지자체 연계 B2G 확장(다국어 생활 캘린더, 공지사항 요약 카드) — 이번 PRD 스코프를 크게 초과해 장기 과제로 이관
5. 집주인 유통 전략의 실제 검증(원룸 집주인 섭외, 실사용 QR 부착)
6. 집주인 알림톡 카테고리 확장(수도 점검, 소음, 주차 등) — 근거 부족 및 번역량 증가로 이번엔 보류, 실사용 피드백 이후 검토
