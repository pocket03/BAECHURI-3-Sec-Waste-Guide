# PRD — 외국인 유학생 분리배출 가이드 (팀 404, 3주 실행판)

> 기반 문서: 서비스기획안_20260810.md · 경쟁사분석_20260810.md · 개발기획안_20260810.md (현재 바탕화면 위치, 4주 가정판)
> 작성일: 2026-08-10 / 팀: 404 (5인: 기획·마케팅 3, 디자인 1, 발표 1) / 대상 지역: **익산시 신동** 원룸촌 / 마감: **2026-08-31 (3주 후)**
> 지원 언어: 한국어·영어·중국어·베트남어 (4개)

## 0. 이 문서의 목적 — 기존 기획 대비 변경점

기존 개발기획안은 **4주 · 팀 구성 미지정 · 언어 2~3개**를 가정했다. 실제 확인 결과와 다른 부분을 아래처럼 조정한다.

| 항목 | 기존 가정 | 실제/결정 | 이유 |
|---|---|---|---|
| 기간 | 4주 | **3주** (2026-08-31 마감) | 실제 남은 기간 확인 |
| 팀 구성 | 3~4인 가정, 역할 미지정 | **5인**: 기획·마케팅 3, 디자인 1, 발표 1 | 실제 팀 구성 확인 |
| 개발 담당 | 프론트엔드 1~2인 가정 | **명시적 개발자 없음** → 기획·마케팅 3인 중 1인이 PM 겸 개발 담당, AI 코딩 어시스턴트 활용해 구현 | 팀에 개발자 역할이 없어 이번 PRD에서 결정 (7절 참고) |
| 언어 수 | 2~3개(권장) | **4개**(한·영·중·베) | 팀 요청. 단, 3주+무개발자 조건과 충돌하므로 8절에 우선순위 강등 순서를 둔다 |
| 대상 지역 | 미정, "원룸촌 1곳" | **익산시 신동** | 확정 |
| 품목 리스트 | "20~30개, 초안 작성" | **리스트 없음, 1주차에 신규 제작** | 확인 결과 아직 없음 |
| QR/배포 | QR 실물 부착 가정 | **시연(데모)만, 실물 부착·실배포 없음** | 팀 결정 |
| 사용자 테스트 | 실제 유학생 2~3명 | **팀 내부 테스트로 대체** | 팀 결정 |

## 1. 배경 및 문제 정의

익산시 신동 원룸촌에 거주하는 외국인 유학생이 한국식 종량제·분리배출 제도를 언어 장벽 때문에 이해하지 못해 무단투기·오배출이 반복되는 문제. 상세 근거·경쟁사 공백 분석은 서비스기획안 1절, 경쟁사분석 문서 참고 — 이 PRD에서는 재인용하지 않고 실행 계획에 집중한다.

## 2. 목표

- **1차 목표**: 3주 뒤 발표에서 "검색 진입 → 결과 확인"과 "QR 진입(시연) → 결과 확인" 두 플로우가 끊김 없이 동작하는 데모를 완성한다.
- **2차 목표**: 4개 언어 전환이 최소 핵심 플로우에서 깨지지 않는다(8절 우선순위 참고).

### KPI (팀 내부 테스트 기준)

| 지표 | 목표 |
|---|---|
| 검색 성공률 | 팀원이 아이콘만 보고 60초 이내 품목 찾기 성공 |
| 언어 전환 정상 동작률 | P0 언어(한·영)는 100%, P1 언어(중·베)는 핵심 화면만이라도 깨짐 없음 |
| QR 시연 → 결과 표시 | 3초 이내 |
| 발표 임팩트 | "언어 장벽"이라는 구체적 원인 + 익산 신동이라는 실제 지역 기준 근거 전달 |

## 3. 범위 (Scope)

### In-scope (4주 기획안 4절과 동일, 언어 수만 변경)

1. 아이콘/사진 기반 품목 검색 (20~30개, 1주차 신규 제작)
2. 다국어 지원 — 한국어·영어·중국어·베트남어 (4개, 우선순위는 8절)
3. QR 현장 가이드 웹페이지 — **시연용**: 실제 인쇄·부착 없이, 발표 중 QR 이미지를 카메라로 스캔하는 방식으로 시연
4. 인포그래픽 카드 UI

### Out-of-scope (3주 내 하지 않음)

- AI 카메라 인식, 위치 기반 지도, 주민 제보 게시판 (기존 향후 로드맵으로 이관)
- 실제 웹 배포(Vercel 등), QR 실물 인쇄·부착 — 시연 데모로 범위 한정
- 외부 사용자(실제 유학생) 대상 검증 — 팀 내부 테스트로 대체

## 4. 사용자 시나리오 / 화면 흐름

3강 워크시트에서 확정한 4개 화면 그대로 사용한다.

| 순서 | 화면 | 사용자가 하는 일 | 다음 화면 |
|---|---|---|---|
| 1 | 언어 선택 화면 | 4개 언어 중 하나 선택 | 아이콘 검색 화면 |
| 2 | 아이콘 검색 화면 | 버릴 물건과 비슷한 아이콘을 그리드에서 선택 | 결과 카드 화면 |
| 3 | 결과 카드 화면 | 선택한 언어로 배출 방법·요일·주의사항 확인 | 검색 화면 복귀(종료) |
| 4 (QR) | QR 스캔 진입 화면 | 분리수거장 QR을 스캔(시연 시 발표 화면의 QR을 스캔) | 결과 카드 화면 |

## 5. 기능 요구사항

### 5.1 아이콘 검색
- 익산 신동 자취생 빈출 품목 20~30개를 사진/아이콘 그리드로 제공. 텍스트 검색은 보조 기능.
- 정확한 한글 품목명을 몰라도 선택 가능해야 한다(핵심 가치).

### 5.2 다국어 (4개, 우선순위 있음 — 8절 참고)
- 언어 전환은 전역 토글로, 페이지 이동 없이 즉시 반영.
- 정적 JSON 기반 i18n(별도 번역 API 불필요, 개발기획안 기술스택 유지).

### 5.3 QR 현장 가이드 (시연용)
- 장소별 URL을 쿼리 파라미터로 구분해 정적 QR 이미지 생성.
- 실제 부착은 하지 않으므로, **발표 자료(슬라이드/노트북 화면)에 QR을 띄워 발표 중 스마트폰으로 스캔하는 시연 방식**으로 대체.
- 최소 1개 가상 장소(예: "신동 A동 분리수거장") 기준으로 동작 확인.

### 5.4 인포그래픽 카드 UI
- 텍스트 최소화, 그림·아이콘 중심, 3초 내 이해 가능한 카드.

## 6. 데이터 요구사항

| 데이터 | 설명 | 신규 작성 여부 |
|---|---|---|
| 품목 리스트 JSON | 품목명·아이콘·카테고리·언어별 설명(4개 언어) | **신규 제작 필요** (기존 리스트 없음) |
| 지원 언어 UI 문자열 JSON | 화면 텍스트의 언어별 매핑 | 신규 |
| 지역 배출 규정 소스 | 익산시 신동 기준, 익산시청 공고 1건을 기준으로 삼아 조사 시간 초과 방지 | 신규 조사 필요 |
| 장소별 배출 요일 데이터(QR용) | 가상 장소 최소 1개 | 신규 |

## 7. 기술 스택 및 개발 담당 (이번 PRD에서 결정)

- **스택**: Next.js + localStorage, 백엔드·로그인 없음, 정적 JSON i18n, 정적 QR 생성 라이브러리 (개발기획안과 동일하게 유지).
- **개발 담당 결정**: 팀 5인 중 명시적 개발자가 없으므로, **기획·마케팅 3인 중 1인을 "PM 겸 개발 담당"으로 지정**하고 **AI 코딩 어시스턴트(Claude Code 등)를 활용해 직접 구현**한다.
  - 근거: 백엔드·로그인 없는 정적 구조라 구현 복잡도가 낮고, AI 어시스턴트 활용이 3주·무전담개발자 조건에서 가장 현실적인 경로.
  - 디자인 담당 1인은 아이콘·인포그래픽 자산 제작과 함께, 필요 시 UI 스타일링(CSS)을 보조한다.
- **이 결정 자체가 최대 리스크**이므로, 1주차 게이트 체크에 "개발 담당자 확정 + 목업 아이콘 그리드 렌더링 성공"을 필수 조건으로 둔다(9절).

## 8. 언어 우선순위 (P0/P1) — 4개 언어 확장에 대한 리스크 대응

3주·무전담개발자 조건에서 4개 언어는 원 기획(2~3개 권장)보다 부담이 크다. 아래 우선순위로 스코프를 조절한다.

| 순위 | 언어 | 조건 |
|---|---|---|
| P0 (필수) | 한국어, 영어 | 3개 핵심 화면 전부 완성도 있게 동작해야 시연 가능 |
| P1 (가능하면) | 중국어, 베트남어 | 2주차 말까지 P0가 끝나지 않으면 이 두 언어부터 순서대로 축소 |

**스코프 조절 규칙**: 게이트를 못 지키면 베트남어 → 중국어 순으로 먼저 줄이고, 한국어·영어는 마지막까지 지킨다.

## 9. 3주 일정

기존 개발기획안의 4주 Phase를 3주로 압축한다. **3주차 중반 이후 기능 동결**은 그대로 유지한다.

### Phase 1 (1주차) — 기획 확정 + 데이터 구조 + 개발 담당 확정

| 담당 | 작업 |
|---|---|
| PM/개발 담당(기획·마케팅 1) | Next.js 프로젝트 세팅, 품목 데이터 JSON 스키마 설계, 목업 아이콘 그리드 렌더링 |
| 콘텐츠/번역 코디(기획·마케팅 1) | 익산 신동 자취생 빈출 품목 20~30개 리스트업, 익산시청 공고 1건 기준 배출 규정 초안 |
| 사용자테스트/QA(기획·마케팅 1) | 4개 언어 번역 톤·용어 가이드 초안, 팀 내부 테스트 계획 수립 |
| 디자인 | 아이콘 세트 방향 확정(문화중립적 픽토그램 기준), 카드 UI 시안 |
| 발표 | 발표 형식·구성 초안 착수 |

**게이트 체크**: 개발 담당 확정 + 목업 데이터로 아이콘 그리드 렌더링 성공. 실패 시 개발 방식(AI 어시스턴트 의존도) 재조정.

### Phase 2 (2주차) — 핵심 검색 UI + P0 언어(한·영) 완성

| 담당 | 작업 |
|---|---|
| PM/개발 담당 | 아이콘 그리드, 결과 카드 컴포넌트, 언어 전환 토글 구현 |
| 콘텐츠/번역 코디 | 전체 품목 배출 규정 콘텐츠 완성, 한국어·영어 번역·1차 검수 |
| 사용자테스트/QA | 중국어·베트남어 번역 착수(가능한 만큼) |
| 디자인 | 전체 품목 인포그래픽 카드 자산 완성 |

**게이트 체크**: 한국어·영어(P0) 기준 전체 품목 검색·조회 가능.

### Phase 3 (3주차) — QR 시연 통합 + 기능 동결 + QA + 발표 준비

| 담당 | 작업 |
|---|---|
| PM/개발 담당 | QR 시연 페이지(쿼리 파라미터 장소 식별), QR 이미지 생성, 모바일 반응형 점검 |
| 전원 | 팀 내부 테스트 2~3회, 버그 우선순위별 수정 |
| 콘텐츠/번역 코디 | P1 언어(중·베) 반영 시도, 안 되면 8절 규칙대로 축소 |
| 발표 | 데모 시나리오(검색→QR 시연 순) 확정, 리허설 |

**게이트 체크(기능 동결)**: 3주차 중반까지 검색·QR 두 플로우가 P0 언어로 끊김 없이 동작. 이후 신규 기능 추가 없음.

## 10. 완료 기준 (Definition of Done)

- 검색 진입 → 결과 카드, QR 시연 진입 → 결과 카드 두 플로우가 한국어·영어로 끊김 없이 동작
- 팀 내부 테스트 기준 검색 성공률·언어 전환 정상 동작 확인
- 발표 5~10분 데모 + 리허설 완료

## 11. 리스크 및 대응

| 리스크 | 대응 |
|---|---|
| 팀에 전담 개발자가 없음 (최대 리스크) | 1주차에 PM 겸 개발 담당 즉시 지정, AI 코딩 어시스턴트 활용, 1주차 게이트에서 목업 렌더링 성공 여부로 조기 검증 |
| 4개 언어가 3주·무전담개발자 조건에서 과할 수 있음 | 8절 우선순위(P0: 한·영 / P1: 중·베)로 스코프 조절 |
| 팀 내부 테스트만으로는 실제 유학생 검증이 안 됨 | 발표 시 "팀 내부 검증 기준"이라는 한계를 명확히 밝히고, 가능하면 지인 유학생 1~2명 섭외를 옵션으로 열어둠 |
| 익산 신동 배출 규정 조사가 오래 걸릴 수 있음 | 익산시청 공고 1건만 기준으로 삼아 시간 초과 방지 |
| 실배포·실물 QR이 없어 "실제 현장 적용"까지는 증명 못 함 | MVP 목표를 "실제 배포"가 아닌 "개념 증명 + 발표용 데모 완성도"로 명확히 설정(팀 결정과 일치) |

## 12. 향후 로드맵 (3주 이후, 참고용)

기존 서비스기획안 8절과 동일: 언어 확대, AI 카메라 인식, 위치 기반 지도·제보 게시판, 대학 연계 실제 QR 배포.
