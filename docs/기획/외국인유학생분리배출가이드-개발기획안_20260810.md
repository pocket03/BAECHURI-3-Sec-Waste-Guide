# 서비스 개발 기획안 — 외국인 유학생 분리배출 가이드 (4주 Phase별 계획)

> 기반 문서: [../기획/외국인유학생분리배출가이드-서비스기획안.md](../기획/외국인유학생분리배출가이드-서비스기획안_20260810.md) · [../기획/외국인유학생분리배출가이드-경쟁사분석.md](../기획/외국인유학생분리배출가이드-경쟁사분석_20260810.md)
> 작성일: 2026-08-10 / 스택: Next.js + localStorage (백엔드·로그인 없음) / 기간: 4주

> **가정**: 팀 구성이 명시되지 않아 일반적인 학부 팀 프로젝트 규모(3~4인: 기획/콘텐츠 1, 프론트엔드 1~2, 번역·검수 1)를 가정해 작업을 배분했습니다. 1인 개발이거나 팀 규모가 다르면 각 phase의 작업량을 인원수에 맞게 재분배해야 합니다.

## 개발 방법론

- **Phase = 1주 단위 마일스톤**, 각 Phase 끝에 "게이트 체크"(그 주까지 반드시 완성되어야 할 산출물)를 둔다.
- **3주차 말 = 기능 동결(Feature Freeze)**. 4주차는 신규 기능 추가 없이 번역 검수·QA·발표 준비에만 집중한다.
- MVP 범위는 [서비스 기획안](../기획/외국인유학생분리배출가이드-서비스기획안_20260810.md) 4절 기준: **아이콘 검색(20~30개 품목) + 다국어 2~3개 + QR 현장 가이드 웹 + 인포그래픽 카드 UI**로 고정한다.
- 문서 관리는 "배경 → 정책/요구사항 → 관련 문서 상호링크" 구조를 따른다(개발 조직의 Confluence/Notion 문서 관리 관행 참고) — 기획 변경이 생기면 이 문서의 관련 절을 함께 갱신하고, 왜 바뀌었는지를 한 줄로 남긴다.

---

## Phase 1 (1주차) — 기획 확정 + 데이터 구조 설계

**목표**: "어떤 품목·언어를 다룰지"와 "기술적으로 되는지"를 가장 빨리 확정한다.

| 담당 | 작업 |
|---|---|
| 기획/콘텐츠 | 대상 원룸촌 1곳 확정, 자취생 빈출 품목 20~30개 리스트업(배달 용기, 택배 테이프, 일회용컵 등), 품목별 배출 규정 초안 작성 |
| 프론트엔드 | Next.js 프로젝트에 라우팅 구조 설계(품목 검색 페이지, QR 진입 페이지), 품목 데이터 JSON 스키마 설계(품목명·아이콘·카테고리·언어별 설명) |
| 번역/검수 | 지원 언어 2~3개 확정(한국어+영어+중국어 또는 베트남어), 번역 톤·용어 가이드 초안 |

**게이트 체크(1주차 말)**: 품목 데이터 JSON 스키마가 확정되고, 빈 화면에서 품목 아이콘 그리드가 목업 데이터로 렌더링되는 것을 확인.

**리스크**: 품목·지자체 규정 조사가 예상보다 오래 걸릴 수 있음 — 대상 원룸촌 1곳으로 좁혔으므로 해당 지자체 홈페이지 공고 1개만 기준으로 삼아 시간 초과를 방지한다.

---

## Phase 2 (2주차) — 핵심 검색 UI + 다국어 콘텐츠

**목표**: MVP의 핵심 기능인 "아이콘 검색 → 결과 카드"와 다국어 전환을 완성한다.

| 담당 | 작업 |
|---|---|
| 프론트엔드 | 아이콘 그리드 UI, 품목 클릭 시 상세 카드(인포그래픽) 컴포넌트 구현, 언어 전환 토글 구현(i18n 텍스트 매핑) |
| 기획/콘텐츠 | 전체 품목의 배출 규정 콘텐츠 완성, 인포그래픽 카드 문구·그림 확정 |
| 번역/검수 | 전체 품목을 지원 언어로 번역, 1차 검수(가능하면 해당 언어 원어민에게 확인 요청) |

**게이트 체크(2주차 말)**: 전체 품목이 3개 언어로 검색·조회 가능하고, 언어 전환 시 깨지는 항목이 없는 것을 확인.

**리스크 대응**: 번역 검수가 지연되면 언어 1개(영어)만 완성도 있게 마감하고 나머지는 3주차로 이월 — 언어 수를 줄이는 것이 스코프 조정 1순위.

---

## Phase 3 (3주차) — QR 현장가이드 통합 + 기능 동결

**목표**: 검색 기능과 QR 진입 흐름을 하나로 통합하고, **이번 주를 끝으로 신규 기능 추가를 중단**한다.

| 담당 | 작업 |
|---|---|
| 프론트엔드 | QR 스캔 시 진입하는 장소별 페이지 구현(쿼리 파라미터로 장소 식별), QR 코드 생성(장소별 URL을 QR 이미지로 변환) |
| 기획/콘텐츠 | 전체 사용자 플로우 테스트(검색 진입 vs QR 진입), 배출 요일 등 현장 정보 최종 확정 |
| 번역/검수 | 전체 콘텐츠 2차 검수, 오역·누락 항목 수정 |

**게이트 체크(3주차 말, Feature Freeze)**: 검색 진입과 QR 진입 두 경로 모두 처음부터 끝까지 끊김 없이 동작. **이 시점 이후 신규 기능은 추가하지 않는다.**

---

## Phase 4 (4주차) — QA·번역 검수·발표 준비

**목표**: 신규 기능 없이 완성도와 신뢰도(번역 정확성)만 끌어올린다.

| 담당 | 작업 |
|---|---|
| 전원 | 실제 사용자 테스트 2~3회(가능하면 외국인 유학생 참여), 버그 리스트업 및 우선순위별 수정 |
| 프론트엔드 | 성능·반응형 점검(모바일에서 QR 스캔 후 접속하는 경우가 많으므로 모바일 뷰 우선 점검) |
| 기획/콘텐츠 | 발표 시나리오 작성(검색 진입 → QR 진입 순서로 시연), 심사 기준(4주 내 개발가능성/파급력/공감 인구수) 대응 논리 정리 |
| 번역/검수 | 최종 번역 검수, 오역으로 인한 신뢰도 저하 리스크 최종 점검 |

**게이트 체크(4주차 말)**: 발표 5~10분 분량의 데모(검색+QR 두 플로우) 완성, 리허설 완료.

---

## 전체 일정 요약

| Phase | 기간 | 핵심 산출물 |
|---|---|---|
| 1. 기획 확정 + 데이터 구조 설계 | 1주차 | 품목 데이터 스키마, 목업 아이콘 그리드 |
| 2. 핵심 검색 UI + 다국어 콘텐츠 | 2주차 | 전체 품목 3개 언어 검색·조회 가능 |
| 3. QR 현장가이드 통합 + 기능 동결 | 3주차 | 검색·QR 두 진입 경로 통합, 이후 기능 추가 중단 |
| 4. QA·번역 검수·발표 준비 | 4주차 | 발표용 데모, 번역 최종 검수 완료 |

## 기술 스택 및 도구

- **프레임워크**: Next.js (기존 스타터 템플릿), localStorage(설정값·최근 검색 등 저장)
- **다국어**: 정적 JSON 기반 i18n 텍스트 매핑(별도 번역 API/서버 불필요)
- **QR**: 정적 QR 생성 라이브러리로 장소별 URL을 이미지화, 인쇄해 현장 부착
- **협업**: 매주 Phase 종료 시점에 팀 리뷰로 게이트 체크, 문서(본 기획안)에 변경 사항을 갱신해 "왜 바뀌었는지" 기록

## 리스크 관리 원칙

1. **스코프는 절대 3주차 이후 늘리지 않는다** — AI 카메라 인식, 지도, 제보 게시판 등은 모두 [서비스 기획안 8절 향후 로드맵](../기획/외국인유학생분리배출가이드-서비스기획안_20260810.md)으로 이관.
2. **언어 수가 스코프 조절의 1차 레버** — 번역 검수가 늦어지면 언어를 줄여서라도 품질을 지킨다.
3. **매주 게이트 체크를 통과 못 하면 다음 Phase 시작 전 스코프를 축소한다.**
