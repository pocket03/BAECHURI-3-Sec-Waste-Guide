## 1. 지금까지 작업한 것

### MVP 핵심 기능 (PRD Must/Should 기준)
- 세입자 화면: 언어 선택(`/guide`) → 오늘의 배출 신호등(또는 집주인이 설정한 공지 배너)·FAQ 버튼형 챗·품목 30종 아이콘 검색(`/search`) → 결과 카드(`/result`, 품목/장소/공지 쿼리 파라미터로 분기). 로그인 불필요
- 알림톡 템플릿 5개(쓰레기 배출 2 · 퇴실 청소 1 · 원룸 공지사항 2) → 한/영/중/베 4개국어 조합 메시지 자동 생성, 카카오톡 발송용 전체 복사
- 데이터: 품목 30종, UI 문자열, 알림톡 템플릿 전부 4개 언어로 작성 완료

### 배포
- GitHub 저장소 2곳(개인용 `BAECHURI_404`, 팀 저장소 `BAECHURI-3-Sec-Waste-Guide`)에 코드 반영
- Vercel 배포 완료: `https://baechuri-404.vercel.app`

### 집주인 로그인 + 건물별 관리 구조 (멀티테넌트)
- **로그인 위치가 `/`(첫 화면) 자체로 통합됨** — 별도 `/admin` 없음. 비로그인 시 `/login`으로 리다이렉트, 로그인하면 그 계정 소유의 건물 데이터만 관리
- Supabase Auth 기반 이메일/비밀번호 로그인, 공개 회원가입 없음(계정은 Supabase 대시보드에서 직접 생성)
- 공지사항·세입자 목록·FAQ·건물 설정 모두 `landlord_id`로 소유자 구분(RLS), 세입자용 조회는 로그인 없이 공개
- **우리 건물 QR·링크**(`/guide?b=<집주인ID>`)로 들어온 세입자에게만 그 집주인이 설정한 FAQ·공지·신호등이 노출됨

### 집주인이 직접 관리하는 콘텐츠
- **공지사항 추가·수정·삭제 + 저장 즉시 문자 발송**: 공지 작성 시 Google Translate로 3개 언어 자동 번역 → Supabase에 저장 → 등록된 세입자 전체에게 바로 문자(SMS) 발송까지 한 번에 처리. 공지별 세입자용 링크·QR도 자동 생성(`/result?custom=<id>`)
- **FAQ 관리**: 집주인이 직접 질문/답변 작성 → 자동 번역 → 그 건물 QR로 들어온 세입자에게만 노출(비어있으면 기본 FAQ 4개로 대체)
- **오늘의 배출 신호등 · 공지 배너**: 건물별 재활용 배출 요일 설정 가능. 공지 배너를 써두면 신호등 자리가 배너로 대체되어 표시(두 기능이 한 칸을 공유)
- **세입자 전화번호 관리**: 전화번호 + 언어 등록, 문자 발송 대상 목록으로 사용

### 문자(SMS) 알림 — 실제 발송
- Solapi 연동 완료(발신번호 등록·API 키 적용), 배포 사이트에서 실발송 테스트 확인됨
- 세입자가 등록한 언어에 맞는 번역본이 발송됨
- 환경변수 3개(`SOLAPI_API_KEY`/`SOLAPI_API_SECRET`/`SOLAPI_SENDER_NUMBER`) 중 하나라도 비어 있으면 자동으로 Mock(콘솔 로그만) 모드로 전환되는 안전장치 유지

### 세입자 → 집주인 문의 기능
- 세입자는 로그인 없이 `/inquiry`에서 전화번호 + 문의 내용을 남길 수 있음 (한국어가 아니면 자동으로 한국어로 번역해서 저장 → 집주인이 읽기 편하게)
- 집주인 대시보드 "문의" 탭에서 건물별 문의 목록 확인, 답장을 입력하면 세입자 언어로 자동 번역되어 SMS로 발송 + 상태가 "답변완료"로 전환
- `inquiries` 테이블: `insert`는 누구나 가능(로그인 없는 세입자용), `select`/`update`/`delete`는 해당 건물 집주인만(RLS)

### 디자인
- 집주인 대시보드(로그인 후 `/`)를 카드 나열식에서 **탭 구조**(발송 / 공지사항 / FAQ / 문의 / 세입자 / 건물 설정)로 재구성. 큰 화면에서는 2단 배치로 여백 활용 — 반응형 문제도 같이 해결됨
- 대시보드 내 모든 카드(발송/공지/FAQ/문의/세입자/건물 설정)를 카드 스타일·아이콘·여백 기준으로 통일해서 팀원이 이어서 편집하기 쉽게 정리
- 세입자 화면(`/guide`, `/search`, `/result`, `/inquiry`)도 카드 스타일·여백·타이포그래피 통일 완료. 공용 헤더 컴포넌트(`TenantHeader`) 도입
- **[피그마_디자인가이드.md](피그마_디자인가이드.md)** 작성 완료 — 색상/타이포/여백 토큰, 컴포넌트 패턴, 전체 화면 인벤토리 정리. 팀원 디자이너가 html.to.design으로 가져오거나 직접 재현할 때 참고 가능

### 보안 최종 점검 (2026-08-21)
- 구글 번역 키·Solapi 키는 서버 환경변수로만 사용(클라이언트 노출 없음), `.env*`는 전부 `.gitignore` 처리, 커밋 이력 전체에서도 노출된 적 없음 확인
- Supabase는 anon key + RLS 조합만 사용(service role key 미사용) — 서버 쪽 권한 상승 경로 없음
- `npm audit` 의존성 취약점 0건, `dangerouslySetInnerHTML`/`eval` 등 XSS 위험 패턴 없음
- 공지사항 문자 발송·문의 답장 API에 로그인 확인 + 소유권 검증(`landlord_id` 일치) 적용됨
- 멀티테넌트 RLS 정책이 실제 프로덕션 DB에 정상 적용된 것을 `pg_policies` 조회로 재확인함
- `/api/translate`는 `/inquiry`가 비로그인 상태로도 호출해야 해서 인증 없이 열려 있음 — 텍스트 2000자 제한을 추가해 과도한 사용량 유출만 방지 (완전한 rate limit은 아님, 남은 리스크로 인지하고 있음)
- `inquiries` insert 정책은 세입자 비로그인 특성상 완전 공개(`with check (true)`) — 건물 QR/링크에 노출된 `landlord_id`를 아는 사람이 스팸을 넣을 수 있는 여지는 남아있음(3주 데모 스코프에서는 감수, 실제 SMS 발송은 집주인이 수동 승인해야 나가서 비용 유출 경로는 아님)

## 2. 남은 작업

| 기능 | 내용 | 비고 |
|---|---|---|
| (선택) **피그마로 디자인 추가 작업** | html.to.design 같은 플러그인으로 배포 사이트를 피그마에 가져와 팀원이 추가로 다듬는 흐름 | [피그마_디자인가이드.md](피그마_디자인가이드.md) 참고. 코드→피그마 자동 동기화는 안 되므로, 피그마에서 바꾼 내용은 다시 코드로 옮겨야 함 |
| (선택) **문자/번역 사용량 포인트·토큰 관리** | SMS·번역 사용량을 포인트/토큰 같은 재화로 제한하는 기능 | 실결제 연동 여부 등 방향이 아직 결정 안 됨. 3주 MVP 스코프에서는 필수 아님 |
| (선택) **문의 접수 rate limiting** | `inquiries` insert가 완전 공개라 스팸 유입 가능성 있음 | 보안 점검에서 발견, 데모 스코프에서는 낮은 리스크로 판단해 보류 |

**완료됨(참고)**: 세입자 화면 디자인 폴리싱, 세입자 → 집주인 문의 기능, 집주인 대시보드 전체 폴리싱, 보안 점검 — 전부 위 섹션에 반영됨
